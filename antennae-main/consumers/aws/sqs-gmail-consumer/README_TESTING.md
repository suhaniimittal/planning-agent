# Testing Guide for SQS Gmail Consumer

This directory contains comprehensive unit tests for the SQS Gmail Consumer application.

## Test Structure

```
tests/
├── __init__.py
├── conftest.py              # Test fixtures and configuration
├── test_client.py          # Tests for agent management (client.py)
├── test_db_utils.py        # Tests for database operations (db_utils.py)
├── test_email_filter.py    # Tests for email filtering logic (email_filter.py)
├── test_gmail_client.py    # Tests for Gmail API interactions (gmail_client.py)
├── test_main.py            # Tests for main orchestration logic (main.py)
└── test_s3_utils.py        # Tests for S3 operations (s3_utils.py)
```

## Running Tests

### Prerequisites

Install test dependencies:
```bash
uv sync
```

### Basic Test Execution

Run all tests:
```bash
uv run pytest
```

Run with coverage:
```bash
uv run pytest --cov=src --cov-report=html
```

Run specific test file:
```bash
uv run pytest tests/test_email_filter.py
```

Run specific test:
```bash
uv run pytest tests/test_email_filter.py::TestEmailFilter::test_should_process_email_whitelist_mode_allowed_sender
```

### Test Categories

Run only unit tests:
```bash
uv run pytest -m unit
```

Run only fast tests (exclude slow ones):
```bash
uv run pytest -m "not slow"
```

### Verbose Output

Run with detailed output:
```bash
uv run pytest -v -s
```

## Test Coverage

The test suite aims for high coverage across all modules:

- **email_filter.py**: Tests all filtering modes, configuration loading, and edge cases
- **gmail_client.py**: Tests Gmail API interactions, message parsing, and attachment handling
- **db_utils.py**: Tests token decryption, database sessions, and error handling
- **s3_utils.py**: Tests file uploads, error handling, and async operations
- **client.py**: Tests agent execution, workflow management, and session handling
- **main.py**: Tests SQS polling, message processing, and orchestration logic

### Coverage Reports

After running tests with coverage, view the HTML report:
```bash
open htmlcov/index.html  # macOS
# or
xdg-open htmlcov/index.html  # Linux
```

## Test Features

### Fixtures

The test suite uses comprehensive fixtures defined in `conftest.py`:

- **Mock objects**: Pre-configured mocks for all external dependencies
- **Sample data**: Representative test data for messages, tokens, and configurations
- **Environment**: Automatic environment variable mocking

### Mocking Strategy

All external dependencies are mocked to ensure:
- Tests run in isolation
- No actual AWS/Google API calls are made
- Consistent, predictable test environment
- Fast test execution

### Async Testing

Async functions are properly tested using:
- `pytest-asyncio` plugin
- `AsyncMock` for async mock objects
- Proper awaiting of async operations

## Troubleshooting

### Common Issues

1. **Import errors**: Ensure you're running tests from the project root
2. **Async warnings**: Make sure `pytest-asyncio` is properly installed
3. **Mock not found**: Check that all external dependencies are properly mocked

### Debug Mode

Run tests with debug output:
```bash
uv run pytest --pdb -v -s tests/test_specific.py::test_function
```

### Test Performance

Profile test execution:
```bash
uv run pytest --durations=10
```

## Best Practices

1. **Test Isolation**: Each test is independent and doesn't rely on others
2. **Mock External Dependencies**: All AWS, Google, and database calls are mocked
3. **Comprehensive Coverage**: Tests cover happy path, edge cases, and error conditions
4. **Readable Test Names**: Test names clearly describe what is being tested
5. **Fixture Reuse**: Common test data and mocks are defined in fixtures
6. **Async Proper**: Async code is properly tested with appropriate tools

## Adding New Tests

When adding new functionality:

1. Add tests in the appropriate `test_*.py` file
2. Use existing fixtures where possible
3. Follow the naming convention: `test_<function_name>_<scenario>`
4. Mock all external dependencies
5. Test both success and failure scenarios
6. Update this README if adding new test categories
